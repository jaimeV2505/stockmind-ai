# Engineering audit & production-readiness report — 2026-10-09 (session 3)

Auditor stance: adversarial. Method: read all code, then **probe it with bad inputs**, reproduce, fix, add regression
tests, re-run. Regression tests were written first and run against the unfixed code (20 failures), then re-run after (0).
Environment limits: no network; no pytest/ruff/TA-Lib/Docker/Postgres; no GitHub access. Tests run with stdlib `unittest`
(Python 3.12.3, numpy 2.4.4, pandas 3.0.2). **Nothing here was run under pytest, ruff, CI, or Docker.**

## 0. Verdict
**NOT production-ready, and not close.** What exists is a small, now better-hardened *foundation*: a candle data model, an
NYSE calendar, data-quality checks, a demo provider and 18 indicators. Roughly 85% of the specified product (all of the web app,
API, auth, database/RLS, provider adapters, scanner, signals, risk, backtester, pattern search, news/AI, alerts, SaaS, admin,
observability, deployment) does not exist. Categories below marked N/I cannot be audited because there is no code; that is itself
the finding, not evidence of safety.

No CRITICAL defects were found *in the code that exists*. That reflects its small attack surface (no network, auth, DB or
user-facing code), not security.

## 2. Findings (defects in existing code)
Format: ID · severity · status · location — evidence → impact → fix → tests.

### HIGH (all fixed)
- **H-1 · HIGH · FIXED · `models.py::Candle.__post_init__`** — Probe: `Candle(close=nan)`, `high=inf`, `volume=nan`, `symbol="aapl"`, `symbol=""`,
  `currency="dollars"` and `ingested_at < market_ts` were all **accepted** (NaN fails every comparison, so every ordering/positivity check passed).
  Impact: one bad provider row silently poisons every downstream indicator, signal and backtest; lowercase/empty symbols defeat de-duplication.
  Fix: finite-real check (bool rejected), strict symbol/currency/exchange/source validation (reject, never silently normalise), reject impossible ingest time, exchange added to `key`.
  Tests: `TestA01CandleInputIntegrity` (7 tests incl. 35 subtests).
- **H-2 · HIGH · FIXED · `calendar.py::is_trading_day` & friends** — Probe: `is_trading_day(datetime(2026,12,25,12,0))` → `True`. `datetime` is a `date` subclass but never equals/hashes as a `date`, so the holiday lookup silently missed.
  Impact: holidays/early-closes treated as normal sessions whenever a caller passes a timestamp — wrong gap detection, fabricated sessions.
  Fix: `_require_date` raises `TypeError` for datetimes; applied to every public calendar function. Tests: `TestA02CalendarTypeSafety`.
- **H-3 · HIGH · FIXED · `quality.py::validate_series`** — Probe: two symbols each missing a different day → `ok=True, missing_dates=[]` (union of dates masked both gaps);
  the same bars from two sources/adjustments → `ok=True` (double-counted data). Fix: raise on multi-symbol/exchange input; new `mixed_provenance` flag. Tests: `TestA04QualityScope`.
- **H-4 · HIGH · FIXED · `quality.py`, `models.py::Candle.freshness`** — Probe: a daily bar ingested mid-session validated `ok=True`; `freshness()` used open+24h as "close" and returned `-1 day, 7:30:00` for a bar ingested 1 h after the real close.
  Impact: still-forming bars can be fed to indicators/signals (repainting = look-ahead), and data-freshness labels (a spec requirement) were wrong.
  Fix: `calendar.bar_close_utc` (session-aware; 1d, 1m/5m/15m only), `QualityReport.incomplete`, corrected `freshness()`; `DemoProvider` emits completed sessions only. Tests: `TestA05IncompleteBars`.
- **H-5 · HIGH · FIXED · `indicators.py::obv`, `::vwap`** — Probe: OBV with a NaN close returned `[90, 90, 90, 100]` (bad bars treated as "unchanged", no NaN); VWAP with a NaN volume returned a clean-looking, skewed number.
  Impact: plausible-but-wrong values with no signal that data was missing. Fix: NaN now propagates (OBV: onward; VWAP: rest of the session); NaN session labels rejected. The NaN contract is documented in the module docstring and pinned by tests for the other recursive indicators. Tests: `TestA06…`, `TestNaNContractForOtherIndicators`.
  Also found while fixing: under **pandas 3** `Series.to_numpy()` is read-only, so the first OBV fix crashed (caught by the existing causality test) — fixed with an explicit copy.
- **H-6 · HIGH · FIXED (partially verified) · `pyproject.toml`, `.github/workflows/ci.yml`** — Reproduced: `pip install -e .` fails with *"Multiple top-level packages discovered in a flat-layout"*; therefore **CI could never pass its first step**. Also default ruff would fail on 15× E741 and 2 unused imports.
  Fix: `[tool.setuptools] packages = []` + build-system (install now succeeds in a fresh venv: *verified*); E741 ignored deliberately (OHLC shorthand); unused imports removed (checked with an AST approximation). **`ruff` itself and the CI workflow have still never run.**
- **H-7 · HIGH · FIXED · `quality.py` (1d alignment)** — A provider stamping daily bars at 00:00 UTC maps to the *previous* New York date: a silent off-by-one-day shift that corrupts every backtest/similarity result.
  Fix: `misaligned_ts` flags any 1d bar whose stamp ≠ that session's open (non-trading-day stamps go to `unexpected_dates`). Adapters must normalise. Test: `test_misaligned_daily_timestamp_flagged`.

### MEDIUM
- **M-1 · FIXED · `calendar.holidays`** — returned the `lru_cache`d dict itself; one caller mutating it altered the calendar process-wide. Now a read-only `MappingProxyType`. Test: `test_holiday_table_is_immutable`.
- **M-2 · FIXED · `relative_volume`** — `inf` when baseline volume is 0. Now NaN. Test added.
- **M-3 · FIXED · `docker-compose.yml`** — dev Postgres published on all interfaces with the well-known password `stockmind`. Now `127.0.0.1` only. Not run (no Docker). Still a dev-only credential; never reuse.
- **M-4 · FIXED (unverified) · `pyproject.toml`** — `zoneinfo` needs a tz database; absent on Windows/minimal images, breaking the whole calendar at runtime. Added `tzdata` dependency (could not be installed here).
- **M-5 · OPEN-MITIGATED · version skew** — code only ever run on pandas 3.0.2 / numpy 2.4.4 while `pyproject` allows pandas ≥2.2 / numpy ≥1.26 (the OBV read-only bug shows these differ). CI matrix now includes the oldest supported pins — **unrun**.
- **M-6 · OPEN (design) · recursive indicators** — one NaN bar makes EMA/RSI/ATR/ADX/MACD NaN forever (fail-closed, safe but operationally harsh). Needs a gap-repair/re-seed policy in the ingestion layer. Contract is now documented + tested.
- **M-7 · OPEN · no third-party numeric validation** — indicators are checked against independent re-implementations and hand calculations only; the RSI "published example" values were typed from memory and are a loose sanity check. Needs TA-Lib cross-check in CI (blocked: no network).
- **M-8 · OPEN · calendar data from memory** — `AD_HOC_CLOSURES` and early-close rules are unverified against nyse.com; unscheduled future closures require manual entry. Annual counts (2019–2024) match widely cited figures.
- **M-9 · OPEN · CI supply chain** — GitHub Actions not pinned to SHAs; no dependency scanning (pip-audit), secret scanning (gitleaks) or SBOM.

### LOW

- L-3 OPEN: pure-Python loops in Wilder smoothing and `swing_points`: 200k bars ≈ 1.3 s. Fine for daily scans; vectorise/numba before intraday full-universe scans.
- L-4 OPEN: git commits use a placeholder identity (`noreply@example.com`); rewrite/re-author before publishing.

## 3. Verified working (evidence = tests that pass in this sandbox)
- 18 indicators numerically consistent with independent references / hand calculations, **causal** at ≥14 truncation points each, and NaN-safe per the documented contract.
- Candle model rejects malformed/impossible data; calendar, session times (incl. DST), early closes, annual trading-day counts 2019–2024.
- Quality validation: duplicates, ordering, gaps (1d/1m/5m/15m), unexpected bars, provenance mixing, forming bars, misaligned stamps.
- Simulated data is always labelled and never emitted as completed live data; no fallback path exists yet.
- Test results: **market-data 43 passed, technical-analysis 45 passed, 0 failed (unittest).**
